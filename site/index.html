Pipeline

Four stages, each one auditable.

Every operation returns a receipt: its sources, its token cost, and whether it declined.

01 · CAPTURE

Sessions in

Turns normalized, duplicates dropped, content chunked to 400 tokens. Durable statements extracted and keyed by what they are about, not what was chosen.

02 · VERSION

Nothing overwritten

A replaced value has its interval closed and keeps its place. The replacement points back at it and carries the reason for the change.

03 · RETRIEVE

A budget, not a dump

Pack size is derived from the measured history — haystack ÷ 46 — and enforced at assembly. Superseded values rank below current ones regardless of match score.

04 · ABSTAIN

Silence is an answer

The pack is assembled first, so the evidence survives even when the claim is withheld. Withholding the answer and withholding the sources are separate decisions.

MCP surface

Twelve tools your agent already knows how to call.

Point Claude Code, Cursor, Windsurf or Codex at one stdio server. No SDK, no glue code.

recall

Query memory with a time window and graph traversal. Returns the pack, compression stats, and abstention.

remember

Store a fact. An id binds it to a topic; because records why it replaced the last value.

why

Walk a fact's supersession chain and return the recorded reasons in one hop.

handoff

Record a decision and the next step for whichever agent picks the work up.

resume

Session-start pack, with cross-agent attribution and the latest handoff.

history

Full version timeline for a fact, including everything it replaced.

learn

Store grounding content verbatim in the knowledge corpus.

list

Snapshot of what is currently stored.

forget

Soft-delete a topic. History is retained; no current value survives.

report

Send retrieval feedback back to HydraDB to improve later ranking.

capture_session

Ingest an entire chat session through the pipeline in one call.

usage

Show rate-limit consumption and the pending write queue, so an agent can pace itself.

Architecture

A policy layer over the graph database.

Lorex does not reimplement a vector database. HydraDB owns storage, retrieval, and graph traversal. Lorex owns what makes retrieved context trustworthy.

FAQ

Frequently asked questions.

A bigger window holds both the old statement and the new one with nothing to separate them, and charges you for all of it every turn. Lorex returns only current values (unless you ask about the past), records why each value changed, and costs 46× less. It also declines when the history does not answer — a window always answers something.
No — and deliberately. HydraDB owns storage, hybrid retrieval, and graph traversal. Lorex is the policy layer on top: versioning, causality, budget enforcement, abstention, identity, and rate limiting. Swapping or upgrading the store does not change the semantics.
Yes — that is the point. All agents pointed at the same workspace read and write one store in HydraDB. Claude Code can record a decision and a next step; Codex on another machine picks both up from resume, with attribution showing who wrote what.
It abstains — with a specific reason and the sources that were considered. Withholding the claim and withholding the evidence are separate decisions, so you can always audit why. The abstention gate is measured lexical overlap between question and evidence, because retrieval scores provably cannot separate answerable from unanswerable questions.
No. Lorex enforces persisted rate limits — writes per hour and day, queries per hour, ingest tokens per day — inside the engine itself. When a cap is hit the agent is told exactly how long to wait. Failed writes retry from a durable queue instead of vanishing.
Nothing is hard-deleted. Forgetting closes a fact's validity window; superseded values keep their place in the timeline. Ask asOf a past date and the old value is the correct answer again.
Every command accepts --mock, which swaps in a full in-process backend — same interface, lexical scoring, simulated graph context. Demos, tests, and the compression benchmark all run offline through it.
